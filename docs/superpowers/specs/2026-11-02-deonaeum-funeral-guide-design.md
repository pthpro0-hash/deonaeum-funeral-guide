# 더나음 장례안내 — 설계문서

- 작성일: 2026-11-02
- 상태: 승인됨 (2026-11-02, 자동 진행 지시)
- 목업: `docs/mockups/` (visual-direction, after-flow, before-flow, sangjo-score)

표기 규칙: **[결정]** 사용자가 정한 것 · **[제안]** 대화 중 Claude가 정하고 사용자가 이의 없이 넘긴 것 · **[빌더]** 만드는 사람이 정해도 되는 것 · **[확인 필요]** 만들기 전에 사실 확인이 필요한 것

## 1. 한 줄 요약

임종 전에는 장례식장과 상조회사를 공식 자료로 차분히 비교해 두고, 임종 후에는 0~4시간부터 장례 후 행정까지 해야 할 일을 시간 순서로 안내하는 무료 모바일 웹. 위치(지금 있는 곳, 고인 주소지)에 따라 그 지역에서 실제로 쓸 수 있는 시설만 보여준다.

## 2. 왜 만드는가

- 운영사 더나음이 직접 필요해서 만드는 서비스다. 누구에게나 닥치는 일이다. **[결정]**
- 임종 후 1~3일차는 할 일이 너무 많고 복잡해서 유족이 상조에 전적으로 의존하게 된다. 이 서비스는 상조를 대체하지 않는다. 대신 **유족이 상조·장례식장의 말을 알아듣고 스스로 판단할 수 있게** 돕는다. 상조 선택에도 도움을 준다. **[결정]**
- 차별점은 **공공 DB·정부·산업 공식 자료에 근거한 최신 실데이터**다. 업체 홍보문이나 추정치를 쓰지 않는다. **[결정]**
- HN상조(곧 출범)와 비즈니스 제휴를 검토 중이다. 하지만 이 서비스는 특정 상조사에 묶이지 않는 더나음 고유 서비스다. **[결정]**

## 3. 목표 · 비목표 · 반목표

**목표**
- 상주·유족에게 실제로 도움이 되는 것이 최우선이다. **[결정]**
- 모든 정보는 무료로 제공한다. **[결정]**
- 공식 정보는 많을수록 좋다. 공식 자료에 있으면 보여준다. **[결정]**
- 전국 단위로 제공한다. **[결정]**

**비목표 (지금 하지 않음)**
- 수익 모델. 기획 단계에서는 고려하지 않는다. **[결정]**
- 중개. 더나음은 운영사일 뿐이다. 업체 연결은 화면의 전화번호를 눌러 직접 거는 데까지만이고, 상담 신청 접수·전달은 하지 않는다. **[결정]**
- 회원가입, 로그인, 서버에 개인정보 저장. **[제안]**
- 장례식장·화장장 예약 대행. 임종 전에는 장례식장 예약 자체가 불가능하다. **[결정]**

**반목표 (기능이 돌아가도 이렇게 되면 실패)**
- 제휴 여부에 따라 노출 순서나 점수가 달라지는 것. 모든 업체를 같은 기준으로 보여준다. **[결정]**
- 출처나 기준일 없이 숫자를 보여주는 것.
- 화려한 디자인. 상조 관련이라 화려하면 안 된다. **[결정]**
- 급한 상주가 첫 화면에서 헤매는 것.

## 4. 사용자와 사용 순간

| 순간 | 누가 | 상태 | 서비스가 할 일 |
|---|---|---|---|
| 임종 전 | 부모 등 가족의 임종을 앞둔 사람, 미리 알아보는 사람 | 차분함, 비교할 시간 있음 | 장례식장 후보와 상조회사를 공식 자료로 비교하고 담아 두게 함 |
| 임종 직후~발인 | 상주·유족 | 당황, 폰으로 급하게 엶 | 지금 할 일을 순서대로 보여주고, 근처 시설과 전화번호를 바로 줌 |
| 장례 후 | 상주·유족 | 행정 처리 | 사망신고, 안심상속, 고인 명의 상조 조회 안내 |

## 5. 정보 구조

```
홈 (두 갈래)
├─ 지금 임종하셨나요? → 임종 후 안내
│    ├─ 시작 질문 2개 (임종 장소, 고인 주소지)
│    └─ 단계별 할 일: 0~4시간 · 4~12시간 · 1일차 · 2일차 · 3일차 · 장례 후
└─ 미리 준비하기 → 임종 전 준비
     ├─ 장례식장 비교
     ├─ 상조회사 비교 (안전 점수)
     └─ 장례 방식·장지 알아두기
```

- 홈은 "지금 임종하셨나요?"(위, 강조)와 "미리 준비하기"(아래, 차분) 두 갈래로 바로 나눈다. **[결정]** (목업: visual-direction 1번)
- 홈 상단에 현재 지역을 표시하고 바꿀 수 있다. **[제안]**

## 6. 임종 후 안내

### 6.1 시작 질문 (목업: after-flow 왼쪽)

두 가지만 묻는다. 둘 다 건너뛸 수 있다. **[제안]**

1. **지금 어디에 계신가요?** 병원 / 자택 / 요양원·요양병원 / 그 외
   - 임종 장소에 따라 사망진단서 절차가 다르다. 병원은 담당 의사가 발급하고, 자택은 경찰 입회 하에 검안 후 시체검안서를 발급한다.
2. **고인의 주민등록 주소지는요?** 시/도 · 시/군/구
   - 화장시설은 고인 주소지(사망 직전일 기준 주민등록) 주민에게 관내 요금을 적용한다. 관외 요금은 지역에 따라 관내의 수 배에서 최대 20배 가까이 된다. 서울시립승화원은 6개월 이상 거주해야 관내로 본다. (출처: 서울시설공단 화장시설 이용 안내)

"지금 계신 곳"은 위치 권한(GPS)으로 받거나 시/군/구를 고르게 한다. **[빌더]**

### 6.2 단계별 할 일 (목업: after-flow 오른쪽)

- 상단 단계 탭: 0~4시간 · 4~12시간 · 1일차 · 2일차 · 3일차 · 장례 후
- 각 할 일은 체크박스, 제목, 한두 줄 설명, **누가 하는지 표시**로 구성한다. **[제안]**
  - `가족` — 가족이 직접 하거나 결정할 일
  - `상조·장례식장` — 상조나 장례식장이 진행하는 일 (가족은 확인만)
- 체크 상태는 그 폰의 브라우저에만 저장한다. 가족 간 공유는 하지 않는다. **[제안]**
- 위치가 필요한 할 일 안에 그 지역 시설 목록이 바로 붙는다. 시설마다 전화 버튼이 있다.

**할 일 목록 초안** (사용자가 준 원문 기반. 문구 다듬기는 **[빌더]**)

## 7. 임종 전 준비

### 7.1 장례식장 비교 (목업: before-flow 왼쪽)

- 기준 지역: 거주지나 연고지. 예약은 임종 후에만 가능하므로 여기서는 비교와 담아두기만 한다. **[결정]**
- 필터: 공설/사설, 빈소 수, 주차 가능. **[제안]** (공공데이터에 있는 항목이면 더 추가 **[빌더]**)
- 항목: 거리, 빈소 수, 안치 가능 구수, 공설/사설, 주차, 전화
- 가격: 빈소 임대료·안치료·장례용품 가격은 API가 없다. 장례식장은 e하늘에 가격 등록 의무가 있으므로 e하늘 가격표로 연결한다. **[제안]**
- "담아두기"로 폰에 저장한다. 담아 둔 곳은 임종 후 안내의 장례식장 목록 맨 위에 나온다. **[제안]**

### 7.2 상조회사 비교 · 안전 점수 (목업: sangjo-score)

**목적:** 가격보다 먼저 "낸 돈이 안전한가"를 100점 만점 점수로 보여준다. **[결정]**

**자료:** 공정거래위원회 「선불식할부거래사업자 정보파일」만 쓴다. **[결정]** (공식 자료만)
- 받는 곳: ftc.go.kr 사업자정보공개 → 선불식할부거래사업자 → 자료 다운로드 (공공데이터포털 3043449 등록, XLS)
- 근거: 할부거래법 제18조. 수시 자동 갱신(최근 수정 2026-09-22). 무료, 이용 제한 없음.
- 들어 있는 항목: 상호, 대표자, 등록번호, 영업 상태, 판매품목 3개(상품명·가격·지급방법), 유동자산·고정자산·자산총계, 지급여력비율, 부채비율, 총선수금, 보전비율, 보전기관·계약유형·보전금액

**점수 = 선수금 보전 50 + 지급여력 30 + 부채 부담 20** **[결정]**

| 항목 | 배점 | 쓰는 값 | 방향 |
|---|---|---|---|
| 선수금 보전 | 50 | 보전비율 | 높을수록 높은 점수. 법정 최소는 50% |
| 지급여력 | 30 | 지급여력비율 | 높을수록 높은 점수 |
| 부채 부담 | 20 | 부채비율 | 낮을수록 높은 점수 |

- **구간(몇 %면 몇 점)은 실제 데이터 분포를 본 뒤 정한다.** 대부분 회사가 한쪽에 몰리지 않게 하려는 것이다. **[제안]** 정한 구간은 사용자 확인을 받는다.
- 정상영업이 아닌 회사(휴업·폐업·등록취소)는 점수를 매기지 않고 "주의"로 표시한다. **[제안]**
- 자료에는 여행·결혼서비스 업체도 섞여 있다. **판매품목이 장례인 회사만** 남긴다. **[제안]** 필터 기준은 **[빌더]**
- 화면 원칙:
  - 목록은 회사별 점수 하나를 보여주고 점수순으로 정렬한다. 상세에서 항목별 점수와 **원래 수치**를 보여준다.
  - "점수 계산 방법"을 전부 공개한다.
  - "이 점수는 공정위 공시로 더나음이 계산한 재무 안전성 점수이며, 정부 공식 등급이 아니다. 서비스 품질과 가격은 포함하지 않는다"는 문구를 붙인다.
  - 항목마다 기준일을 표시한다. 재무 수치는 회사가 제출한 결산 기준이라 최신이 아닐 수 있다.
- **판매 상품 정보도 보여준다.** 공시에 있는 주요 상품 3개의 이름, 가격, 지급방법을 상세에 표시한다. ("공식 정보는 많을수록 좋다" 원칙) **[결정]** 상품끼리 구성이 달라 가격으로 순위를 매기지는 않는다. **[제안]**
- 이미 가입한 사람용 안내: 공정위 해약환급금 계산기, 상조회사 폐업 시 '내상조 그대로'. **[제안]**
- 상조회사는 전국 단위로 비교한다. 지역 필터를 적용하지 않는다. **[제안]**

### 7.3 장례 방식·장지 알아두기

- 종교별 장례 절차 차이, 추모 방법 네 가지(봉안, 자연장, 묘지, 해양장)를 설명한다.
- 지역의 공설·사설 장사시설 목록을 보여준다.
- 화면 설계는 아직 하지 않았다. 7.1과 같은 형식(필터 + 목록 + 출처)으로 만든다. **[빌더]**

## 8. 위치 필터링 규칙

위치는 **필요한 할 일 안에서만** 쓴다. 기준은 두 가지다. **[제안]**

| 기준 | 무엇에 쓰나 | 임종 전 | 임종 후 |
|---|---|---|---|
| 지금 있는 곳 (거리) | 장례식장, 봉안·자연장·묘지 시설의 거리순 정렬 | 거주지·연고지로 대신함 | 임종 장소 |
| 고인 주민등록 주소지 (요금) | 화장시설 관내/관외 구분 | 고인 주소지 | 고인 주소지 |

- 화장시설 목록에서는 관내 시설이 먼저 나오고, 관외 시설에는 "관외 요금 적용" 경고를 붙인다.
- **관내 판정 규칙 [제안]:** 공설 화장시설과 고인 주소지가 같은 시군구면 "관내 가능성 높음", 다르면 "관외 요금 가능성"으로 표시한다. 모든 화장시설에 "관내 범위와 요금은 시설에 직접 확인" 문구와 시설 공식 안내 페이지 링크를 붙인다. 손으로 정리한 관내 범위표는 만들지 않는다("공식 자료만" 원칙). 광역 화장장(여러 시군 공동 이용)이나 거주 기간 요건은 시설 안내 페이지로 넘긴다. 요금 금액은 공식 자료로 받을 수 없으면 표시하지 않는다. 사설 화장시설에는 관내 표시를 하지 않는다.
- 시설 공공데이터에 좌표가 없으면 주소를 좌표로 바꿔야 한다(지오코딩). **[빌더]** 방식을 정할 것.
- 같은 화면에 지도를 띄울지는 **[빌더]**가 정한다. 목록이 기본이다.

## 10. 디자인

**방향: "비움" — 하라 겐야식 동양적 여백** **[결정]** (목업: visual-direction 1번, after-flow, before-flow, sangjo-score)

- 고급스럽되 절제한다. 화려하면 안 된다. **[결정]**
- 한지처럼 따뜻한 흰 바탕에 아주 옅은 종이 질감(불투명도 0.07 이하)을 깐다. 색은 먹색 하나다.
- 강조색을 따로 두지 않는다. 경고(관외 요금, "주의" 상조)에만 낮은 채도의 적갈색 한 가지를 쓴다.
- 서체: 제목은 Noto Serif KR(명조), 본문은 Pretendard. 한국어 줄바꿈은 `word-break: keep-all`.
- 버튼: 각진 먹색 사각형(모서리 2px). 보조 동작은 밑줄 링크로 한다.
- 아이콘, 이모지, 그라데이션, 장식 이미지는 쓰지 않는다.
- 목업에서 쓴 색 값 (출발점, 다듬기는 **[빌더]**):

| 이름 | 값 | 용도 |

- 다크 모드는 만들지 않는다. **[제안]**

## 11. 만드는 방식

사용자가 직접 Claude와 만든다. **[결정]** 기술 방식은 Claude가 정했다. 사용자의 이전 프로젝트 「전국문화축제 지도」(`../고옹API_축제`)와 같은 구조다. **[제안]**

- **변경 (구현 착수 시 확인 결과) [제안]:** 공정위 자료가 XLS(OLE2)라 PowerShell 대신 Python 파이프라인으로 바꿨다. 갱신은 PC 작업 스케줄러 대신 GitHub Actions 주간 실행으로 바꿨다(사용자의 공연정보 프로젝트가 같은 방식으로 전환됨). 공공데이터는 API(인증키 미승인) 대신 키가 필요 없는 공공데이터포털 파일데이터를 쓴다. 지오코딩은 키 없는 Nominatim(OSM)을 쓰고 결과를 캐시한다.
- **수집:** PowerShell 스크립트로 공공데이터포털 API와 공정위 XLS를 받아 JSON으로 저장한다. 원본은 백업 폴더에 남긴다.
- **생성:** 화면용 데이터 파일을 만든다. 상조 점수 계산도 이 단계에서 한다.
- **화면:** 서버 없는 정적 모바일 웹이다. 위치는 Leaflet + OpenStreetMap을 쓴다(지도를 쓸 경우).
- **배포:** GitHub Pages에 올린다.
- **갱신:** Windows 작업 스케줄러로 정기 실행한다(수집 → 생성 → 배포). 주기는 **[빌더]**가 정한다. 상조 공시는 수시 갱신이라 월 1회 이상을 권장한다.
- **인증키:** 기존 data.go.kr 인증키를 재사용한다. 인증키는 로컬 스크립트에만 두고 공개 저장소에 올리지 않는다.
- **개인정보:** 로그인과 서버 저장이 없다. 임종 장소, 고인 주소지, 체크 상태, 담아 둔 업체는 그 폰 브라우저(localStorage)에만 저장한다. URL에 넣지 않는다.
- **방문 통계 도구는 쓰지 않는다.** 화면 하단에 운영자 정보(더나음), 연락처, "개인정보를 수집하지 않습니다" 고지를 둔다. **[제안]**

- **근거와 문의 안내 [결정]:** 모든 점수·수치·안내에 근거 자료(기관, 자료명, 기준일, 링크)를 명시한다. 상조회사 상세에는 "자세한 상품·계약 내용은 해당 상조회사에 문의하세요"와 전화번호를 붙인다.
- **범위 [결정]:** 1~12절 전체를 체계적으로 한 번에 만든다. 단계별 출시는 하지 않는다.
- **배포 [결정]:** 개인 GitHub 계정(pthpro0-hash)의 GitHub Pages에 올린다.
- **진행 방식 [결정]:** 이후 질문 없이 자동으로 진행한다. 인증키 발급 등 사용자가 직접 해야 할 일은 모아서 한 번에 넘긴다.
- **상조 점수 구간 [제안]:** 원래 사용자 확인을 받기로 했지만 자동 진행 지시에 따라 Claude가 실제 데이터 분포로 정한다. 정한 구간과 근거는 화면의 "점수 계산 방법"과 작업 기록에 남긴다.
