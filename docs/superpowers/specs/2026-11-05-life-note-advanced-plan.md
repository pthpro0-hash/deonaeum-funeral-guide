## 1. 한 줄 요약

죽음을 준비하는 서비스가 아니라 **지금의 나를 정리해 두는 노트**로 바꾼다. 장례 바람, 상속, 연명의료, 디지털 계정, 전하고 싶은 말은 "인생 노트"의 한 장(章)이 된다. 부고 발송은 노트의 맨 마지막 장이고, 본인이 지정한 사람이 확인하고 직접 보낸다.

## 2. 왜 바꾸나

- 한국에서는 죽음을 미리 이야기하는 것을 꺼린다. "내 부고 준비"라는 이름은 정확하지만 첫 클릭을 막는다.
- 실제로 이 메뉴에서 하는 일(바람 적기, 계산, 계정 정리, 가족에게 전하기)은 "인생 정리"에 더 가깝다.
- 다만 **정직함은 지킨다.** 밝은 말로 감싸되, 각 기능이 무엇이고 법적 효력이 있는지 없는지는 그대로 밝힌다. 포장이 사실을 가리면 안 된다. **[제안]**

## 3. 원안 PRD 검토

## 4. 브랜딩 방향 [제안]

### 4.1 이름 후보

| 후보 | 느낌 | 비고 |
|---|---|---|
| **나의 인생 노트** (추천) | 따뜻하고 쉬움. 5060에게 익숙한 "노트" | 메뉴명·화면 제목 모두 자연스러움 |
| 나의 인생 백서 | 단정하고 무게감 | "백서"가 정부·기업 문서로 읽힐 수 있음 |
| 스마트한 인생 정리 | 실용적, 젊은 느낌 | 슬로건으로 적합, 메뉴명으로는 김 |

추천 조합: 메뉴명 **"나의 인생 노트"**, 한 줄 소개 **"지금의 나를 정리해 두는 스마트한 방법"**.

### 4.2 말투 원칙

- 주어는 "나". "고인", "임종", "사후" 같은 단어는 첫 화면과 메뉴명에서 쓰지 않는다. 기능 설명 안에서는 정확히 쓴다.
- 밝게, 그러나 가볍지 않게. 이모지·느낌표·"걱정 끝!" 같은 광고 말투 금지(디자인 '비움' 유지).
- 언제든 고칠 수 있다는 점을 반복한다. "오늘의 마음을 적어 두고, 바뀌면 고치세요."

### 4.3 바꿔 쓰는 말

| 지금 | 바꾼 말 (메뉴·첫 화면) | 기능 안 설명에서는 |
|---|---|---|
| 내 부고 준비 | 나의 인생 노트 | 그대로 정확히 |
| 나의 마지막을 적어 두기 | 지금의 나를 정리해 두기 | |
| 장례에 대한 나의 바람 | 나의 마지막 의식은 이렇게 | "장례 방식"이라고 명시 |
| 디지털 자산 정리 | 내 디지털 생활 정리 | |
| 사전연명의료의향서 | 내 치료에 대한 결정 | 제도명은 정식 명칭 그대로 |
| 법정상속분 계산 | 우리 가족 상속 미리 보기 | "법정상속분"을 부제로 |
| 생존 확인 | 안부 확인 | |
| 부고 발송 | 소식 전하기 | 대리인 화면에서는 "부고"로 정확히 |

### 4.4 첫 화면 구조

Part 1 홈은 지금처럼 **임종 직후 가족**이 1순위다(급한 사람이 먼저). 인생 노트는 본인용이라 성격이 다르므로:
- 홈의 세 번째 블록을 "나의 인생 노트"로 바꾸고 말투를 위 원칙으로 고친다.
- 인생 노트 전용 첫 화면(`#/note`)을 따로 둔다. 지인에게 공유하거나 복지관 안내문에 넣을 때 이 주소를 쓴다. 장례 안내로 바로 보이지 않게.
- 기존 `#/plan/...` 주소는 새 주소로 넘겨준다(이미 저장한 기기 데이터 유지).

## 5. 정보 구조 (IA) [제안]

```
나의 인생 노트 (#/note)
 ├── 0. 노트 표지 — 진행률, 마지막으로 다듬은 날, "가족에게 전할 노트 만들기"
 ├── 1장. 나의 이야기        — 살아온 길(짧은 연표), 고마운 사람들, 좋아하는 것   ← 신규
 ├── 2장. 마음 전하기        — 그룹별 메시지, 꼭 전할 말 (유언 아님)              ← 신규
 ├── 3장. 소식 전할 사람들   — 그룹, 제외 대상 (기기 저장)                       ← 신규
 ├── 4장. 마지막 의식        — 장례 바람(기존), 영정사진(기존), 부고 문안 초안     ← 확장
 ├── 5장. 내 치료에 대한 결정 — 사전연명의료의향서(기존)
 ├── 6장. 재산과 상속        — 상속 미리 보기(기존), 유언 방식·자필 양식(기존), 재산 위치 메모 ← 확장
 ├── 7장. 내 디지털 생활     — 계정 정리 체크리스트(기존)
 └── 8장. 믿고 맡길 사람     — 대리인 정하기, 전달 키트 인쇄                      ← 신규
```

1장을 맨 앞에 두는 이유: 처음 들어온 사람이 "죽음" 대신 "내 이야기"로 시작하게 한다. 부담 없는 질문부터 답하면 뒷장까지 이어 쓸 가능성이 높다.

## 6. 기능 정의

모든 기능은 단계를 표시한다. **1단계 = 서버 없음(지금 구조)**, **2단계 = 서버 없음 + 공유 기능**, **3단계 = 서버 필요(Part 3-B)**.

### F-10. 노트 표지와 진행률 (1단계)
- 장마다 "적음 / 비어 있음"만 표시. 점수나 경쟁 요소 없음.
- "마지막으로 다듬은 날" 표시. 6개월이 지나면 "한 번 다시 읽어 볼까요?" 한 줄.
- 완료 기준: 처음 온 사용자가 표지에서 무엇을 할 수 있는지 10초 안에 안다.

### F-11. 나의 이야기 (1단계, 신규)
- 짧은 연표(태어난 곳, 학교, 일, 가족, 기억에 남는 일) 5~10줄. 모두 선택 입력.
- 고마운 사람과 그 이유, 좋아하는 음식·노래·장소.
- 쓰임: 부고 문안·추도사·영정 옆 약력의 재료가 된다. 장례 때 가족이 "고인이 좋아하신 노래"를 몰라 헤매는 일을 줄인다.

### F-12. 마음 전하기 메시지 (1단계, 원안 F-01 일부)
- 그룹(가족, 친척, 오랜 친구, 직장 동료 등)별로 다른 메시지. 개인별 메시지도 가능.
- 모든 메시지 상단에 고정 문구: "마음을 전하는 글이며 법적 효력이 있는 유언이 아닙니다."
- 재산 분배처럼 보이는 문장을 쓰면 유언 방식 안내를 한 줄 띄운다(단어 기반 안내, 막지는 않음).

### F-13. 소식 전할 사람들 (1단계 기기 저장, 원안 F-02)
- 이름과 그룹만 적어도 된다. 전화번호는 선택.
- 가져오기: CSV 파일 업로드(파일은 기기 안에서만 읽음). 휴대폰 주소록 선택은 지원 브라우저(안드로이드 크롬의 연락처 선택 기능)에서만 보이게 **[확인 필요]**.
- "연락하지 않을 사람" 표시.
- 화면에 고지: "적은 연락처는 이 기기에만 있습니다. 기기를 바꾸거나 브라우저 기록을 지우면 사라지니, 전달 키트를 인쇄해 두세요."

### F-14. 부고 문안 초안 (1단계, 원안 F-01)
- 장례 바람·영정사진·나의 이야기를 바탕으로 부고 문안을 미리 만든다. 날짜·빈소는 빈칸(대리인이 그때 채움).
- 종교별 표현 차이(소천, 선종, 별세 등)는 사용자가 고른다 **[확인 필요: 표현별 쓰임]**.

### F-15. 믿고 맡길 사람 + 전달 키트 (1단계)
- 대리인 1~2명 이름과 관계만 적는다(서버에 안 올림).
- **전달 키트** = 인쇄·PDF 묶음: 장례 바람, 부고 문안 초안, 소식 전할 사람 목록(그룹별), 마음 전하기 메시지, 계정 정리 체크리스트, 연명의료의향서 등록 여부, 유언 보관 장소 메모.
- 본인이 장별로 넣을지 뺄지 고른다. 봉투에 넣어 대리인에게 직접 건네는 것을 기본 경로로 안내한다.
- 이 단계에서 "사후 발송"은 사람(대리인)이 키트를 보고 한다. 시스템 개입 없음.

### F-16. 소식 전하기 도우미 (2단계, 원안 F-04 대체)
- 대리인이 임종 후 Part 1 "부고 알리기" 할 일에서 연다.
- 부고 문안의 빈칸(빈소, 발인 일시, 상주)을 채우면, 그룹별로 **대리인 자신의 휴대폰에서** 카카오톡 공유·문자 공유 버튼을 누른다. 서버 발송 없음.
- 본인의 마음 전하기 메시지는 그룹별로 함께 붙여 보낼지 대리인이 고른다.
- 문제: 본인 기기에만 있던 노트를 대리인이 어떻게 여나? → 2단계는 **전달 키트의 QR**: 노트 내용을 담은 파일을 대리인 기기에서 불러오는 방식 **[제안, 기술 검토 필요]**. 파일은 본인이 비밀 문구로 잠그고, 문구는 봉투에 따로 적는다.

### F-17. 안부 확인 (3단계, 선택, 원안 F-03 대체)
- 본인이 켜야만 동작. 주기(월·분기) 선택.
- 미응답 시 동작은 단 하나: 대리인에게 "OO님과 한동안 연락이 닿지 않았어요. 직접 안부를 확인해 보세요." **부고를 보내거나 노트를 여는 데 쓰지 않는다.**
- 본인이 응답하면 바로 끝. 대리인 알림 전 유예 기간을 둔다.

### F-18. 대리인 확인형 소식 전하기 (3단계, 원안 F-03·F-04)
- 노트를 서버에 암호화 보관(종단간 암호화 우선 검토) **[법검토]**.
- 발송 조건: 대리인 2명 모두 "사망을 확인했다"고 확인 → 대기시간(예: 24시간) 동안 본인 기기로 "누군가 소식 전하기를 시작했습니다. 아니라면 취소하세요" 알림 → 그 뒤 대리인이 발송 버튼을 누른다. 대리인이 1명뿐이면 대기시간을 늘린다.
- 사망진단서 업로드는 기본으로 받지 않는다. 받는다면 확인 직후 삭제(보관 안 함) **[법검토]**.
- 일괄 발송(알림톡·SMS)은 비용·사업자 요건 확인 뒤 결정(16절).

### F-19. 장례 실무 연결 (1단계부터, 원안 F-04 대체)
- 부고 흐름의 다음 화면은 Part 1 "임종 후 할 일"이다. 장례식장 찾기, 상조 비교(안전 점수), 화장장 예약 안내.
- 본인이 노트에 "가입한 상조"를 적어 두었다면 그 회사 연락처를 맨 위에 보여 준다(본인 선택이므로 중립 원칙과 충돌하지 않음).
- 제휴사(HN상조 등)는 같은 정렬 규칙 안에서 "제휴" 표시만 한다. 특정 업체로 가는 단독 팝업·큰 버튼은 두지 않는다. **[결정 필요: 16절 3번]**
- 화환 주문은 Part 4 범위. 이 문서에서는 다루지 않는다.

### F-20. 재산 위치 메모 (1단계, 신규)
- 금액이 아니라 **어디에 무엇이 있는지**만: 거래 은행 이름, 보험사, 부동산 주소 메모, 유언장 보관 장소.
- 비밀번호·계좌번호·주민번호 입력 칸은 만들지 않는다. 입력란에 "비밀번호는 적지 마세요" 고정.
- 사후에는 안심상속 원스톱 서비스로 조회할 수 있다는 안내를 같이 둔다.

## 11. 성공 기준

- 장례 바람 + 부고 문안 + 전달 키트 인쇄까지 15분 안에 끝난다.
